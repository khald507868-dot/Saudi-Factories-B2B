# نقل تحديثات الويب إلى Flutter

تستخدم الصفحات نفس مشروع Supabase وجداول الموقع ودواله. جميع التعديلات على واجهة التطبيق موجودة داخل `lib/`، مع تحديث قاموس `i18n.js` المشترك فقط لإضافة النصوص الجديدة.

## ما نُقل

- الرئيسية: إعلانات التخفيضات، صور الفئات التي يرفعها المدير، إحصاءات المنصة من `get_public_stats`، والمنتجات الأكثر مبيعاً مع معرض الصور وأسعار الشرائح والعملات.
- عناوين التوصيل: استبدال شعار الرئيسية بالعنوان المختار وسهم يفتح قائمة سفلية للاختيار والتعديل والحذف وإضافة عنوان. تفتح الإضافة `delivery_location_page.dart` للبحث عن عنوان أو اختيار نقطة على الخريطة وتأكيدها، ثم `delivery_address_page.dart` لإدخال الاسم والمبنى والطابق والوحدة وتعليمات التوصيل. يدير `delivery_address_service.dart` عناوين الحساب والاختيار الافتراضي في Supabase، ويحتفظ بعناوين الزائر على جهازه فقط. التفعيل والصلاحيات في [DELIVERY_ADDRESSES.md](DELIVERY_ADDRESSES.md)، والترحيل [20260910060000_delivery_addresses.sql](../supabase/migrations/20260910060000_delivery_addresses.sql) مخصص لتشغيله من مالك المشروع.
- دليل المصانع: البحث وتصفية الفئة والمنطقة، وعرض المصانع المعتمدة ومصنع المستخدم نفسه.
- المصنع: الرئيسية والمنشورات والنبذة والمنتجات، المتابعة وعدد المتابعين الحقيقي، رابط الموقع، تعديل المنتجات والمنشورات والصور والفيديو وشرائح الأسعار والعنوان والسجل.
- المنتج: تحديث البيانات من الخادم، حالة المنتج المفقود، معرض الصور، المفضلة، الكمية المكتوبة واختيار شريحة السعر، بيان المبالغ، التقييمات وتوزيع النجوم، ووسم المشتري الموثق الصادر من الخادم.
- السلة: كتابة الكمية، سعر الشريحة الفعلي، الرسوم والضريبة، إرسال التعديلات المؤجلة قبل الطلب، ومفتاح منع تكرار إنشاء الطلب.
- المحادثات: بطاقة المنتج في مسودة الإرسال وفي الرسائل المستلمة، الإرسال من لوحة المفاتيح، صور وفيديو بروابط خاصة مؤقتة، ومنع تكرار الرسائل بسبب الصدى اللحظي.
- الطلبات والمفضلة والفواتير: صفحات مستقلة مرتبطة بلوحة الحساب، حالات الدفع، وتأكيد استلام الدفع بعد التأكيد داخل الواجهة للمصنع المالك أو المدير.
- الحساب: إيرادات الطلبات المدفوعة خلال 14 يوماً، بيانات المستخدم، تغيير البريد بتأكيد Supabase، وتسجيل الخروج إلى الرئيسية كزائر.
- الإدارة: المصانع المعلقة والمعتمدة والمرفوضة، سبب الرفض والعودة للمراجعة، وإدارة صور الفئات وإعلانات التخفيضات.
- إعلانات التطبيق: بانر بالصور مكان عبارة الرئيسية، مع السحب ونقاط التنقّل وروابط اختيارية. رفع الصور والترتيب والتعديل والإخفاء والحذف متاحة للمدير وحده، بصلاحيات RLS وStorage. تُعرض الصور كاملة وتختفي المساحة للزائر عند غياب الإعلانات المنشورة. التفعيل والاستخدام في [PROMOTIONS.md](PROMOTIONS.md).
- الإعدادات: المكان الوحيد لتغيير اللغة وعملة العرض، وفيها 30 لغة و30 عملة بأسعار العرض المرجعية نفسها في `currency.js`. يُحفظ الاختيار وتتحدث الشاشات فورًا، ويمكن للزائر الوصول إليها من زر الإعدادات في صفحة الحساب دون تسجيل دخول.
- التنقل: شريط سفلي عائم مستدير بتدرج زجاجي خفيف، ومؤشر متحرك يشمل أيقونة القسم واسمه. يدعم الأقسام الستة وشارات الرسائل والسلة، ويحترم مساحة مؤشر الجوال واتجاه اللغة وتقليل الحركة.

## قرارات النقل

- تحديث الواجهة البصرية: خلفية `#F6F7F6`، أشرطة بيضاء، حدود بطاقات `#C7DFCE`، وأزرار `#1F6B42` من ملفات الويب. ترتيب الرئيسية: الإعلانات، ثم الفئات، ثم المنصة بالأرقام، ثم أكثر المنتجات مبيعاً. تُجمّع قوائم الحساب في أقسام، ويُختصر الرسم عند غياب الإيرادات. رمز الريال يُرسم من مسارات SVG نفسها في `green-frames.css`.

- الواجهة تحتفظ بتخطيط الجوال والتنقل الأصلي في Flutter. أُزيل قسم خريطة المناطق من الرئيسية بطلب المالك، وتبقى تصفية المنطقة متاحة في دليل المصانع. خريطة عنوان التوصيل صفحة مستقلة تُفتح عند إضافة العنوان أو تغيير موقعه، ولا تعيد قسم اكتشاف المصانع إلى الرئيسية.
- مزامنة العناوين تخص دفتر عناوين الحساب وعنوانه المختار، وتظهر التغييرات على الأجهزة الأخرى عند تحميل القائمة أو تحديثها. لا تُنقل عناوين الزائر تلقائياً إلى الحساب، ولا يُستخدم حفظ محلي بديل عند فشل حفظ عنوان المسجّل. الميزة لا تضيف العنوان تلقائياً إلى سجلات الطلبات أو الفواتير.
- تحويل العملات للعرض؛ الفواتير والطلبات المثبتة تعرض الريال. إجمالي العرض يُحسب من سعر الوحدة الظاهر بعد التقريب. الخادم يحسب مبلغ الطلب النهائي.
- دالة إنشاء الطلب الحالية ترفض خلط مصنعين في السلة. التطبيق يوضح ذلك قبل الإرسال، ولا يحذف منتجات مصنع آخر مؤقتاً لتجاوز القيد.
- QR الموجود في صفحة الفاتورة يحمل مرجع الطلب وبياناته الفعلية. لا تُنسخ بيانات بائع أو أرقام ضريبية ثابتة من قالب صفحة الويب.
- الصور والفيديو في المحادثات تبقى داخل `chat-media` الخاص؛ روابطها موقعة ومحددة المدة.
- لم تُنفّذ أي ترحيلات على قاعدة البيانات. يلزم وجود الترحيلات التي تعتمد عليها نسخة الموقع الحالية، بما فيها التقييمات والمتابعة وشرائح الأسعار وبطاقات المنتجات.

## التحقق

إعلانات الرئيسية: نجحت اختبارات التطبيق الـ56 بعد الإضافة، بينها 19 اختباراً للإعلانات وصلاحيات واجهتها وتحديث الرئيسية. نجح التحليل وبناء الويب للإصدار النهائي. اختُبرت الصور والتنقّل بصرياً على عرضَي 430 و320 بكسل باستخدام بيانات وهمية داخل متصفح اختبار منفصل. نجح سكربت `scripts/test_home_promotions.mjs` في 12 فحص PostgreSQL معزولاً، تشمل إعادة الترحيل وحواجز القراءة والكتابة وملفات الصور؛ لم يُطبّق الترحيل على قاعدة الموقع الفعلية.

شاشة البداية تعرض ترحيبًا متحركًا لمدة ثلاث ثوانٍ من أول إطار، ثم تستبدل مسارها باختيار الحساب للزائر أو الرئيسية للمسجّل. الرسم متجهي محلي، ولا يتطلب تنزيل صور أو مكتبات إضافية. اختبارات `splash_page_test.dart` تغطي التوقيت الدقيق، الرجوع، إلغاء التنقل عند إغلاق الشاشة، الحركة العادية والمخفّضة، والأحجام الصغيرة مع تكبير النص.

الشعار يحفظ حروف Segoe UI Black المستخدمة فعليًا في شعار الويب كمسارات رسم داخل `wordmark_paths.dart`، بألوان الهوية الأصلية وموضع B2B المرتفع. لذلك لا يعتمد على الخط العربي أو وجود خط Windows على جهاز المستخدم. يمكن إعادة توليد المسارات على Windows باستخدام `scripts/gen_flutter_wordmark.ps1`؛ لا يُضمّن ملف الخط في التطبيق. بعد هذا التعديل نجحت اختبارات التخطيط الثمانية، بما فيها التحقق من الاسم المقروء للشعار، ونجح التحليل دون ملاحظات.

من جذر المستودع:

```sh
node scripts/gen_i18n.mjs
node scripts/gen_flutter_map.mjs
node scripts/check_flutter_integrity.mjs
```

من `app_flutter`:

```sh
flutter pub get
dart analyze --fatal-infos
flutter test
flutter build web --release --no-tree-shake-icons
```

اختبارات `web_parity_test.dart` تغطي حدود شرائح الأسعار، الرسوم والضريبة، تقريب العملات، تعديل سعر السلة، قيم الفاتورة المثبتة وصلاحية تأكيد الدفع، بطاقات المحادثة، سلامة الروابط، عرض البطاقات على شاشة بعرض 320، واختيار العملة.

إذا منع Windows تشغيل مترجم مؤثرات Flutter، يمكن تشغيل هذه الاختبارات باستخدام `flutter test --no-test-assets` لأنها لا تحتاج تلك المؤثرات. اختبار اختيار العملة يستعمل تأثير النقر العادي. إذا حجز OneDrive مجلد البناء، تُنفّذ الاختبارات على نسخة مؤقتة من الملفات خارج OneDrive.

أضيف مسار تحقق Flutter إلى GitHub Actions. لم تُنفّذ عمليات إرسال الطلبات أو الرسائل أو تأكيد الدفع على بيانات الإنتاج أثناء التحقق.

نتيجة التحقق المحلي بعد تحديث الواجهة: نجحت الاختبارات الـ27 عبر `flutter test`، ونجح `dart analyze --fatal-infos` وفحص مفاتيح الترجمة. اختبارات التخطيط الجديدة تغطي عرضي 320 و430 وتكبير النص حتى 130%. تعمل معاينة Flutter في Chrome، ورُوجعت الرئيسية والحساب والفئات بصريًا. حُلت مشكلة منع أداة البناء المحلية بإجراء المستخدم على جهازه؛ لم تُنتج حزمة إصدار نهائية ضمن مراجعة التصميم.

قبل الحفظ في GitHub نجح أيضًا `flutter build web --release --no-tree-shake-icons` في نسخة التحقق المؤقتة. ولعدم توفر Python محليًا، نُفذت فحوص JavaScript وSQL وروابط الويب المكافئة عبر Node: نجح فحص 25 سكربتًا و26 ترحيلًا و370 مرجعًا محليًا؛ يستمر GitHub Actions في تشغيل سكربتات Python الأصلية.
