# تفعيل حذف الحساب

تم التفعيل على مشروع `yhofxryhlrrwzztfowpa` بتاريخ 2026-09-13:

- نُفّذ ملف `20260913230000_account_deletion.sql` وحده على قاعدة البيانات.
- نُشرت الدالة `delete-account`، الإصدار 1، وحالتها `ACTIVE`.
- فحص الصلاحيات الفعلي: `anon` و`authenticated` لا يستطيعان تنفيذ دالة قاعدة البيانات؛ `service_role` يستطيع.
- اختبارات الدالة المنشورة: طلب OPTIONS يعيد 204، والجلسة المفقودة أو غير الصالحة تعيد 401، وGET يعيد 405.
- لم يُحذف أي حساب حقيقي في اختبارات النشر. مسار الحذف اختُبر محليًا بمحاكاة الخدمات.

## إعادة النشر عند الحاجة

أضيف زر «حذف الحساب» أسفل تسجيل الخروج في `web-settings.html`، مع تأكيد صريح قبل التنفيذ.

1. نفّذ `supabase/migrations/20260913230000_account_deletion.sql` في SQL Editor.
2. انشر المجلد `supabase/functions/delete-account` بوصفه Edge Function باسم `delete-account`.
   باستخدام Supabase CLI بعد تسجيل الدخول:

   ```sh
   supabase functions deploy delete-account --project-ref yhofxryhlrrwzztfowpa --no-verify-jwt --use-api
   ```

   تعطيل تحقق البوابة هنا لا يجعل الحذف متاحًا للزوار: الدالة تتحقق بنفسها من Bearer token
   عبر `auth.getUser(token)` قبل أي قراءة أو حذف. هذا يدعم أيضًا مفاتيح المشروع publishable.
   لا تضع `SUPABASE_SERVICE_ROLE_KEY` في HTML أو JavaScript الواجهة؛ Supabase يوفره داخل الدالة.
3. جرّب بحساب اختبار مستقل بلا طلبات: الإلغاء يبقيه، والتأكيد يحذف حساب Auth وبياناته التابعة
   ثم يعيد المستخدم للرئيسية. تأكد من عدم إمكان تسجيل الدخول بالحساب المحذوف.

## السلوك والحدود

- يستخرج الخادم هوية المستخدم من الجلسة الموثقة؛ لا يقبل معرّف حساب يختاره العميل.
- يمنع الحذف عند وجود أي طلب شراء أو بيع مرتبط بالحساب، بما فيها الطلبات المكتملة والملغاة؛
  العلاقات الحالية في قاعدة البيانات تمنع حذف هذه الحسابات للحفاظ على الطلبات والفواتير للطرف الآخر.
  تظهر رسالة تشرح ضرورة التواصل مع إدارة التطبيق لمعالجة هذه الحالة.
- تُحذف ملفات Storage التي يملكها الحساب باستخدام Storage API، ثم حساب Auth وبياناته التابعة بـ cascade.
  لا تُحذف صفوف Storage مباشرة عبر SQL. سجلات الطلبات لا تُحذف.
- حذف الملفات وحساب Auth ليس معاملة ذرية واحدة. إذا تعطل التنفيذ بعد حذف بعض الملفات، قد تبقى
  بيانات الحساب بلا تلك الملفات؛ تظهر رسالة فشل ويستطيع المستخدم إعادة المحاولة. لا تعرض الواجهة نجاحًا قبل تأكيد Auth.
- يحتفظ Supabase بإمكان صلاحية JWT قديم حتى انتهاء مدته؛ حارس التطبيق الحالي يتحقق بـ getUser
  قبل إتاحة الصفحات. حذف حساب Auth يلغي جلساته، وتُنظف جلسة المتصفح بعد النجاح.
- لم تُنفّذ عملية حذف على أي حساب حقيقي أثناء تطوير هذا التغيير.
